## 大模型应用开发岗/Agent开发岗还需要自行补充的后端技能

#### 1. 缓存中间件（Redis）

大模型应用中需缓存 LLM 调用结果、会话状态、向量检索临时数据，减少重复计算和模型调用成本；

可实现接口限流、分布式锁，保障高并发下的系统稳定性；

也是 Agent 多轮对话中状态存储的核心工具，支撑 Memory-based Agent 的落地。

**推荐资料：**

- [Redis 官方文档](https://redis.io/docs/)
- [极客时间《Redis 核心技术与实战》（蒋德钧）](https://uaxe.github.io/geektime-docs/%E5%90%8E%E7%AB%AF-%E6%9E%B6%E6%9E%84/Redis%E6%A0%B8%E5%BF%83%E6%8A%80%E6%9C%AF%E4%B8%8E%E5%AE%9E%E6%88%98/Redis%E6%A0%B8%E5%BF%83%E6%8A%80%E6%9C%AF%E4%B8%8E%E5%AE%9E%E6%88%98/)
- [黑马程序员 Redis 快速入门](https://www.bilibili.com/video/BV1cr4y1671t/?spm_id_from=333.337.search-card.all.click&vd_source=f66cebc7ed6819c67fca9b4fa3785d39)
- [小林coding图解](https://mp.weixin.qq.com/s/7EDme1HJK7eGnhYQD2DHAA)

#### 2. 消息队列（RocketMQ/RabbitMQ/Redis Streams）

大模型推理、工具调用等操作存在高耗时特性，通过消息队列实现异步解耦，避免用户同步等待；

支撑任务重试、延迟执行、优先级调度，解决 Agent 多步任务中的执行容错问题；

实现分布式系统的组件通信，适配大模型应用的微服务架构。

**推荐资料：**

- 官网教程：[RabbitMQ Tutorials](https://www.rabbitmq.com/getstarted.html)
- [尚硅谷的 RabbitMQ 教程](https://www.bilibili.com/video/BV1sw4m1U7Qe/?spm_id_from=333.337.search-card.all.click&vd_source=f66cebc7ed6819c67fca9b4fa3785d39)
- [RocketMQ 官方文档](https://rocketmq.apache.org/zh/docs/quick-start/)

#### 3. 数据库（MySQL/PostgreSQL/MongoDB）

MySQL/PostgreSQL 用于存储用户信息、对话日志、模型配置等结构化数据，是大模型应用的基础数据存储载体；

PostgreSQL 的 JSONB 类型可灵活存储 Agent 非结构化中间状态，pgvector 扩展可兼顾轻量向量检索；

MongoDB 天然适配大模型应用中的非结构化数据（如工具返回结果、模型生成内容）存储需求。

推荐资料：

- [黑马程序员MySQL教程](https://www.bilibili.com/video/BV1Kr4y1i7ru/?spm_id_from=333.337.search-card.all.click&vd_source=f66cebc7ed6819c67fca9b4fa3785d39)
- [pgvector GitHub Usage](https://github.com/pgvector/pgvector)
- [MongoDB Atlas Vector Search 教程](https://www.mongodb.com/products/platform/atlas-vector-search)

#### 4. 容器化与部署（Docker/Docker Compose）

Docker 可实现大模型应用的环境隔离与一键部署，解决开发、测试、生产环境不一致问题；

可为 Agent 生成的代码提供安全执行沙箱，限制资源占用和网络访问，规避恶意代码风险；

Docker Compose 可快速编排大模型应用所需的多组件（模型服务、缓存、数据库），降低部署复杂度。

**推荐资料：**

- [Docker - 从入门到实践](https://yeasy.gitbook.io/docker_practice/)
- [狂神说 Java - Docker 系列](https://www.bilibili.com/video/BV1og4y1q7M4/?spm_id_from=333.337.search-card.all.click)

#### 5. API 设计与通信协议（REST/SSE/gRPC/MCP）

REST 是大模型应用对外提供服务的基础协议，支撑通用接口调用；

SSE 是国内大模型流式输出的主流协议，实现 “打字机效果” 的核心能力；

gRPC 提升微服务间的通信效率，适配大模型应用的分布式架构；

MCP 协议实现 Agent 与外部工具的标准化连接，减少不同工具的适配开发成本。（上面的计划表中包括了）

**推荐资料：**

- [MDN - Using server-sent events](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)：了解为什么大模型偏爱它而不是 WebSocket
- [gRPC 官方指南](https://grpc.io/docs/languages/python/basics/)

#### 6. 分布式基础与服务治理

大模型开发岗需面对模型服务、推理服务、应用服务的分布式部署场景，掌握服务注册发现、负载均衡基础，保障服务的高可用；

理解分布式事务、数据一致性，解决多组件协作中的数据问题；

适配企业级大模型应用的规模化部署需求。

**推荐资料：**

- **凤凰架构（透明多级分发）：** [The Fenix Project](https://icyfenix.cn/)。这是周志明老师写的电子书，建议重点看“服务发现”、“负载均衡”和“可靠性通信”章节。

#### 7. 可观测性基础（日志 / 监控 / 链路追踪）

大模型和 Agent 的行为链路长、非确定性强，结构化日志可快速定位问题；

监控指标（调用量、延迟、错误率、Token 消耗）可实时掌握系统运行状态，及时发现异常；

链路追踪能可视化 Agent 的决策和执行过程，是调试大模型应用的核心能力。

**推荐资料：**

- [LangSmith 文档](https://docs.smith.langchain.com/)：看看它的设计思想——如何可视化 Trace、如何进行自动化评估

#### 8. 认证与安全（OAuth2.0/API Key 管理 / 权限控制）

大模型应用需对接用户系统和第三方工具，OAuth2.0 是标准化的授权方式，保障第三方服务访问的安全性；

API Key 的安全管理规避模型密钥、工具密钥泄露风险；

权限最小化控制可限制 Agent 和用户的操作范围，避免大模型应用产生非预期的真实世界副作用。

**推荐资料：**

- [OAuth.net](https://oauth.net/2/)
- [阮一峰的 OAuth 2.0 教程](https://www.ruanyifeng.com/blog/2019/04/oauth_design.html)：极其经典的科普
